# Oracle → Databricks semantic dictionary (wave 0)

No `oracle-plsql` dialect skill exists in these repos, so this file **is** the dialect for this run.
Every entry is decided here once, centrally, and children implement it as written. A child that
meets an Oracle behavior with no entry here **stops and reports**; it does not decide for itself and
it does not "clean up" source behavior it judges to be a bug. Parity is against the source's actual
output, quirks included.

Money is `DECIMAL(14,2)` end to end (source columns are `NUMBER(12,2)`; the wider target type is
deliberate headroom, not a semantic change). Any `DOUBLE` in a money lineage rejects the PR.

| ID | Oracle behavior | Target rule | Why it bites |
| --- | --- | --- | --- |
| D-01 | `LEAST` / `GREATEST` propagate `NULL`: `GREATEST(NULL, 0)` is `NULL`. | Spark `least`/`greatest` **ignore** `NULL` and would return `0`. Wrap every one: `CASE WHEN a IS NULL OR b IS NULL THEN NULL ELSE greatest(a, b) END`. Never emit a bare `least`/`greatest` in a converted expression. | Silent, one-sided, and lands directly on money and unit counts. The single most likely cause of a recon mismatch in this estate. |
| D-02 | `NVL(x, y)` | `coalesce(x, y)` — two-arg only. `NVL2`/`DECODE` fallbacks are separate entries. | Safe; listed so children do not reach for a `CASE`. |
| D-03 | `DECODE(a, b, r1, r2)` matches `NULL` to `NULL` as equal. | `CASE WHEN a <=> b THEN r1 ELSE r2 END` (null-safe equality), not `CASE WHEN a = b`. | `CASE WHEN a = b` yields `ELSE` for `NULL` inputs; `DECODE` yields `r1`. Hits the tier/status/kind mappings in `pkg_plans`, `pkg_rating`, `pkg_dunning`. |
| D-04 | `ROUND(x, 2)` on `NUMBER` rounds half away from zero. | `round(cast(x AS DECIMAL(38,10)), 2)` on a **decimal** input — Spark's decimal `round` is HALF_UP, which matches. Rounding a `DOUBLE` does not. | Half-cent values are manufactured on purpose by the tax split (D-11); this is where they resolve. |
| D-05 | `TO_DATE(s, 'DD-MON-YY')` maps a 2-digit year into the **current** century: `'31-DEC-99'` → 2099, used in `pkg_plans.fn_entitlement` as an open-ended sentinel. | Parse as `2000 + YY` explicitly. Do **not** use a bare `to_date(s, 'dd-MMM-yy')`: Java's 80-year pivot resolves `99` to **1999**, flipping the sentinel from "never ends" to "ended in the past" and dropping every subscription. | A silent, total data-loss bug that passes every type check. |
| D-06 | `pkg_ow_util.f_str2dt` returns `NULL` for any unparseable string (`WHEN OTHERS THEN NULL`). | The target **quarantines** the row with reason `BAD_DATE`, counts it in recon, and continues (STOP A). This is an intentional divergence from source, which silently nulls. Recon compares money over the surviving population on both sides and reports the quarantine count beside every money figure; loaded + quarantined must equal source rows; >5% of source rows quarantined halts the unit. | The one place we knowingly differ from source. It must be stated, not discovered. |
| D-07 | `TO_CHAR(ts, 'YYYYMMDD') BETWEEN ...` — dates compared as strings, which silently drops the time component. | Keep the truncation: `date_format(ts, 'yyyyMMdd')` string compare, or an explicit `to_date(ts)` compare. Do not "upgrade" to a timestamp comparison. | `USAGE_EVENTS.occurred_at` has a time component. A timestamp comparison includes or excludes boundary-day events differently and changes rated units. |
| D-08 | `ROWNUM <= 1` applied after `ORDER BY s.starts_on DESC` in an inline view; `starts_on` is **not** unique, so ties break arbitrarily. `fn_entitlement` is worse — `AND ROWNUM = 1` with no `ORDER BY` at all. | Pin a deterministic tiebreak: `row_number() OVER (PARTITION BY tenant_id ORDER BY starts_on DESC, id DESC) = 1`. Record it in the recon report as an **unverified path**: for tenants with tied `starts_on`, target and a given source run may legitimately differ. | Not fixable, only pinnable. Pretending it is deterministic is how a recon "mismatch" burns a day. |
| D-09 | `sp_finalize_rating` **persists** `rollover_units` as `GREATEST(g_quota_units - g_used_units, 0)` — which is not the `g_rollover_units` (three-month banked, double-capped) it just computed. | Persist the source formula verbatim, including its `NULL` propagation per D-01. Do not reconcile the two. | A converter that "fixes" this to the computed value breaks parity on every row. The discrepancy is the contract. |
| D-10 | `pkg_invoicing.compute_preview` calls `pkg_rating.compute_rating` and then reads `pkg_rating.g_overage_amount` — package-global state, not a table read. | Invoicing recomputes rating **inline** in its own dataflow. It must not read `RATING_RESULTS`. No package globals in the target: values pass as explicit columns/parameters. | `RATING_RESULTS.rollover_units` differs from the in-memory value (D-09), and finalize may not have run for the period at all. Reading the table changes invoice totals. |
| D-11 | Tax: hardcoded `0.0825`, `NULL`-propagating (`(fee + overage) * rate`), then split into two **unrounded** halves (`g_tax/2` twice) which round to 2dp on insert into `NUMBER(12,2)`. | Preserve the constant as a named constant — do not parameterize, do not look up a rate table. Preserve the halves and let each half round at write time, per D-04. | `ROUND(tax/2, 2) * 2 <> ROUND(tax, 2)` for odd half-cents, so invoice lines legitimately do not sum to the header tax. Recon must compare lines to lines and header to header, never lines-summed to header. |
| D-12 | Credit burn-down in `sp_issue_invoice`: ordered `issued_on, id` loop that sets `remaining_amount = GREATEST(remaining - v_credit, 0)` and then decrements `v_credit` by the note's **pre-update** `remaining_amount` — over-applying credit across notes. | Reproduce exactly, in order. This is the one unit of work in the estate that is genuinely sequential: implement it as an ordered scan (window-based running total or a driver-side loop over a small per-tenant set), never as a set-based join. Document the ordering key in the unit's notes. | A set-based translation is not equivalent, and the difference shows up as customer-visible money. |
| D-13 | Tier break at 101 units; `overage = ROUND(first * rate + second * rate * 1.5, 2)`. Suspension proration applies **after** tiering: `factor = (period_end - suspended_on + 1) / (period_end - period_start + 1)`, then `ROUND(billable)` to a whole number and `ROUND(amount, 2)`. | Preserve the constant `101`, the `1.5` second-tier multiplier, and the order of operations. Oracle `DATE - DATE` yields days: use `datediff(...) + 1`. Proration applies only when `status_cd = 20` **and** `suspended_on` falls inside the period. | Reordering proration before tiering changes the tier split and the money. |
| D-14 | `pkg_ow_util.f_md5_uuid`: `MD5` of the input, lowercased hex, sliced `8-4-4-4-12`. All primary keys of derived rows (`RATING_PERIODS`, `RATING_RESULTS`, `INVOICES`, `INVOICE_LINES`, `DUNNING_ATTEMPTS`, `NOTIFICATIONS`) come from it. | Reimplement identically (`lower(md5(input))` + the same slicing) and use these ids as the `MERGE` keys, together with `ns`. Same input string, byte for byte, including the `TO_CHAR(date,'YYYY-MM-DD')` and literal suffixes (`'invoice'`, the line number). | Deterministic keys are the reason `MERGE`-based restart is safe here. Recompute them wrong and every rerun doubles the data. |
| D-15 | Sequence-fed surrogates with no business meaning: `CUST_SEQ_NO`, `EAV_ID`, `HIST_ID`, `LOG_ID`, `ATTEMPT`-adjacent ids from `NOCACHE` sequences (`trg_customer_master_seq`, `trg_entity_attr_value_seq`, `trg_billing_audit_log_id`). | Do not port sequences one-for-one and do not attempt to reproduce specific values. Assign at load. These columns are **excluded from value comparison** in recon; recon asserts uniqueness and cardinality instead. Sequence-derived values that *are* compared (D-14 ids) are not sequences at all. | Comparing surrogate values produces guaranteed, meaningless mismatches. |
| D-16 | Trigger-resident rules, retained as pipeline logic (STOP A): `trg_sub_no_uncancel` (status `30` can never be changed away), `trg_usage_events_check` (`units > 0` and `kind_cd` must exist in `CODES` for `code_type='USAGE_KIND'`), `trg_customer_master_seq` (`cust_name_upper = UPPER(cust_name)`, `row_version_no` defaults via `NVL(...,1)`). | Explicit, tested pipeline logic and a dictionary entry each. A validation failure quarantines with its own reason code and counts toward the 5% halt — it does not silently drop. | These are the rules the app relies on without knowing they are in the database. |
| D-17 | `_HIST` capture triggers (`trg_customer_master_hist`, `trg_subscriptions_hist`) retired (STOP A). | Existing rows migrate as first-class tables; `HIST_DT` parses under D-06; `HIST_OP` (`UPD`/`DEL`) is preserved. No new `_HIST` writes from the target. Delta history covers changes from the first target run forward and **cannot** reconstruct pre-cutover history. A PR that drops `_HIST` as audit noise, or recreates trigger-style capture, is rejected. | A deleted customer's last known state exists only in `CUSTOMER_MASTER_HIST`. |
| D-18 | Old-style outer joins: `t.id (+) = i.tenant_id` (keeps invoices), `p.id (+) = s.plan_id` (keeps subscriptions). | Translate direction-by-direction to explicit `LEFT JOIN` with the non-`(+)` side preserved. Re-derive the direction from the `(+)` placement every time; do not pattern-match from a sibling unit. | Reversing an outer join direction changes row counts, not just values, and reads as a "data loss" bug in recon. |
| D-19 | `NOT NULL` on `RATING_RESULTS.quota_units` / `.subscription_id` while the source code can compute `NULL` for both (no covering plan / no subscription). In source, finalize raises and the tenant's run aborts. | The target quarantines that tenant-period with reason `NO_COVERING_PLAN` and continues; it does not abort the unit and does not substitute a zero. Counts toward the 5% halt. | Source failure modes must map to a declared target behavior, not to an uncaught exception in a notebook. |
| D-20 | `EXECUTE IMMEDIATE` used for a static lookup (`f_code_desc`) and a static delete (`invoice_lines`), plus `pkg_ow_util.log_msg` — an autonomous transaction that commits independently and swallows every error. | Convert the dynamic SQL to its static equivalent. `BILLING_AUDIT_LOG` migrates as data but is **out of parity scope**: it is written by an autonomous transaction that survives caller rollback and is pruned at 90 days by `JOB_PURGE_AUDIT_LOG`, so source and target contents cannot be made to agree. Target job logging is structured logging, not rows in this table. | Trying to reconcile a swallowed-error audit log is unbounded work with no business value. Declaring it out of scope is the decision. |
| D-21 | CUSTBILL fixed-width feed (copybook `CBCUST01`): `BILL-AMT` is `PIC 9(10)V99` — an **implied** decimal, no point in the file. `REC-TYPE` `01`=invoice, `02`=credit. Source performs no validation; malformed records pass through. | Divide the raw integer by 100 into `DECIMAL(14,2)`. Short/long lines, non-numeric amounts, and unknown `REC-TYPE` values quarantine with reason `BAD_FIXEDWIDTH` and count toward the 5% halt. Never coerce a malformed amount to zero. | Reading `BILL-AMT` as a plain integer inflates money by 100×; it is the classic copybook error and it looks perfectly valid downstream. |
| D-22 | Physical design: 25 indexes, no partitioning, no dist/sort keys. | Liquid clustering on the declared natural key plus `ns`. Do not port indexes one-for-one; do not add `ZORDER` on top. | Index-for-index porting produces a target tuned for an access pattern that no longer exists. |
