OW_BILLING application-code census
===================================

Scope and method
----------------
Repository-wide searches covered the 20 table names returned by tables.txt,
FREEPDB1, 52521, ow_billing, and the package names returned by
plsql_objects.txt. The entries below distinguish Oracle consumers from estate
definition, fixture, harness, test, probe, and documentation references. Paths
are repository-relative; line numbers refer to the checked-out branch.

Runtime Oracle consumers
------------------------

services/legacy-billing/app/reports.py:32-70
  Category: runtime consumer.
  Connection: oracle_connect at 122-131 uses ORACLE_USER, ORACLE_PASSWORD,
  ORACLE_HOST, ORACLE_PORT (default 52521), and ORACLE_SERVICE (default
  FREEPDB1). No PL/SQL call is made.
  Reads: STATUS_SQL reads INVOICE_HEADER and outer-looks up CODES by
  INV_STATUS; LINE_SQL reads INVOICE_HEADER, INNER-JOINs INVOICE_LINE by
  invoice_id, and outer-looks up CODES; BALANCES_SQL reads CUSTOMER_MASTER.
  Endpoint dispatch is at 154-155 and 171. Oracle errors are handled by the
  query wrapper and surfaced as the endpoint's 503 path at 134-149 and
  158-174.
  The line report's inner join excludes INVOICE_LINE rows without a matching
  INVOICE_HEADER row.

services/legacy-billing/app/reports.py:73-79
  Category: runtime consumer.

procs/harness/oracle_record.py:1-16, 72-86, 164-180, 216-229
  Category: harness/test execution path; not a read-only census consumer.
  Connects to OW_BILLING through DB_USER, DB_PASSWORD, DB_HOST, DB_PORT
  (default 52521), and DB_SERVICE (default FREEPDB1). Reads mapping and probe
  SQL, then invokes mapped PL/SQL with cursor.callfunc/cursor.callproc.

  PKG_INVOICING, and PKG_DUNNING. reset_baseline at 164-180 issues DELETEs
  against notification, dunning, invoice, rating, usage, credit-note,
  subscription, history, and tenant tables, then commits. Do not run this
  reset path for a read-only census.

scripts/tp_pain/mongodb.py:27, 64-85, 107-121

  Connects to Oracle with DB_HOST/DB_PORT (default 52521), DB_USER, DB_PASSWORD,

  CUSTOMER_MASTER for a conversion batch, USER_TAB_COLUMNS for
  CUSTOMER_MASTER and CUSTOMER_MASTER_HIST, and USER_TRIGGERS for
  CUSTOMER_MASTER. The script documents its connection as OW_BILLING and
  issues no DML.

Search exclusions and negative findings
---------------------------------------

scripts/tp_break/mongodb.py references legacy-shaped date/EAV terms but uses
MongoDB data-plane insert/delete operations only; it does not connect to
Oracle.

The repository search also matched unrelated dependency virtualenv files and
the separate insurance Oracle estate. Those hits were excluded from this
OW_BILLING inventory because they do not reference the billing schema or its
package set.

No application-code ROWID usage was found in the inspected OW_BILLING paths.
The only case-insensitive code-scan setting in the relevant probe is
re.IGNORECASE in scripts/tp_pain/mongodb.py:51; Oracle source uses UPPER for
CUST_NAME_UPPER in schema/02_horror.sql:353 and LOWER for MD5 hex formatting
in packages/01_pkg_util.sql:26. No session-wide case-insensitive comparison
setting was found.
