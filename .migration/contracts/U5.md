# U5 contract — invoicing (decision-first)

Unit U5, wave 3, class XL / proc-heavy. Content below is the approved mapping-spec v1.2
contract for the invoicing tables. Nothing here amends the approved mapping.

- Mapping: `.migration/03_mapping_spec.{md,json}` v1.2 (APPROVED)
- Tolerances: `.migration/02_tolerances.{md,json}` v1.0 (APPROVED, STOP A)
- Canonicalization: `.migration/recon_canonicalization.json` v1.2
- Target db: `ow_tp_mongodb_032752`; every document carries `ns: "mongo_032752"`.
- Registered write targets: `ow.invoices`, `ow.credit_notes`. These targets have no
  collision with another unit; U6's `dunning_attempts[]` embed lands via the sequential
  U5→U6 batch that owns `ow.invoices`.

## Mapping rows

| Collection | Root table | Rows | `_id` (key strategy) | Fields |
|---|---|---:|---|---|
| `invoices` | `INVOICES` | 3 | source `ID` verbatim | `tenant_id`, `period_id`, `issued_at`, `subtotal`, `tax`, `total`, `status_cd` |
| `invoices.lines[]` | `INVOICE_LINES` | 2 | element key `line_no` (source `LINE_NO`) | `id`, `line_type`, `description`, `amount` |
| `credit_notes` | `CREDIT_NOTES` | 5 | source `ID` verbatim | `tenant_id`, `issued_on`, `amount`, `remaining_amount` |

The row counts are the NS=demo fixture counts and are checked by the loader and
reconciliation harness. Oracle is read-only after fixture seeding. `INVOICE_LINES`
rows are embedded under their parent invoice ordered by `line_no`; an invoice with no
lines carries an explicit empty `lines: []`. The contract expects zero orphan lines
(every `INVOICE_ID` resolves to an `INVOICES` row); an orphan is an undeclared anomaly
and halts the load.

### `dunning_attempts[]` — U6-owned, model-compatible, not populated

The approved `invoices` entry also declares a `dunning_attempts[]` embed
(`DUNNING_ATTEMPTS`, element key `attempt_no`). That array's content is owned by U6 in
the same sequential batch. U5 does not create or populate `dunning_attempts[]` (the
field is absent, which is compatible with U6 adding the array), and U5's recon subset
mapping excludes that embed with the exclusion recorded verbatim in the emitted subset
file and declared as a deferred path in the unit PR and progress ledger. All other
mapping content is verbatim from the approved spec.

## Type contract applied to this unit

| Oracle | Columns here | BSON | Canonicalization |
|---|---|---|---|
| VARCHAR2 | `tenant_id`, `period_id`, lines `id`, `line_type`, `description` | string | `empty_string_is_null` |
| TIMESTAMP(6) | `issued_at` | date | UTC, truncate to milliseconds |
| DATE | `issued_on` | date | UTC, truncate to milliseconds |
| NUMBER(12,2) | `subtotal`, `tax`, `total`, lines `amount`, `amount`, `remaining_amount` | Decimal128 | decimal round, half-even |
| NUMBER(4,0) | `status_cd` | int | — |

Source NULL becomes an explicit BSON null; NULL is not missing.

## Index plan

- `invoices`: `(tenant_id, status_cd, issued_at)` for overdue scans; unique
  `(period_id, tenant_id)` is NOT asserted (no source constraint).
- `credit_notes`: `(tenant_id, issued_on)`.

The unique `(invoice_id, attempt_no)` contract for dunning attempts is preserved
structurally by the `attempt_no` element key inside the single invoice document (U6).
No other collection or database is written by U5.

## Stored-procedure replacement (`PKG_INVOICING`)

| Source object | Replacement |
|---|---|
| `compute_preview` | `InvoicingService.compute_preview` |
| `fn_invoice_preview` | `InvoicingService.invoice_preview` |
| `fn_invoice_lines` | `InvoicingService.invoice_lines` |
| `sp_issue_invoice` | `InvoicingService.issue_invoice` |

The application port preserves: the latest-covering subscription selection
(`starts_on DESC`, `ROWNUM <= 1`) joined to `plans` for plan code/fee; the U4 rating
integration for the overage amount; the credit pool as the sum of positive
`remaining_amount` with `NVL(...,0)` per row; `tax_exempt_yn` with `NVL('N')` and a
missing tenant defaulting to non-exempt; tax rate `0.0825` with Oracle NULL
propagation (`(plan_fee + overage) * rate` is NULL when either operand is NULL); the
charge cap `ROUND(plan_fee + overage + tax, 2)` and credit application
`LEAST(credit, NVL(cap, credit))`; the five preview line concepts (plan, usage
overage, regional tax `tax/2` unrounded, local tax `tax/2` unrounded, credit notes with
`-credit_applied` total); deterministic ids
`period_id = md5_uuid(tenant_id || YYYY-MM-DD(period_start))` and
`invoice_id = md5_uuid(period_id || 'invoice')`; the insert-then-update upsert to
status `20`; `sp_issue_invoice`'s delete+rebuild of ALL lines per invoice — that whole
rebuild is ONE Oracle transaction boundary, preserved as single-document atomicity by
rebuilding the embedded `lines[]` in one document write; subtotal accumulated from
plan/usage lines, tax from tax lines, `total = ROUND(subtotal + tax - credit, 2)`
(Oracle `ROUND` half-away-from-zero); and the oldest-first (`issued_on, id`)
credit-note decrement loop with its verbatim
`GREATEST(remaining_amount - running, 0)` / `GREATEST(running - remaining, 0)`
running-counter semantics. Credit-note decrements plus the invoice document write run
in one MongoDB session transaction (the source's multi-document transaction).

The Oracle audit-log write is suppressed: U7 owns `billing_audit_log`. The service
retains the audit sink seam with the source message strings.

Recon for this unit is a child self-check (`run_mode=fixture`): the harness runs against
the deterministic read-only `NS=demo` Oracle fixture. The CLI exposes that as
`--mode live` (its modes are `live`, `snapshot`, `continuous`), as the prior unit
wrappers do. The parent owns the independent live gate. Stored-procedure parity is
evidenced by replaying the recorded Oracle transcripts in
`procs/oracle/transcripts/invoicing/*.json` against the migrated service.
