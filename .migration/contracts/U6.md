# U6 contract — dunning (decision-first)

Unit U6, wave 3, proc-heavy. Content below is the approved mapping-spec v1.2 contract for
the dunning tables. Nothing here amends the approved mapping.

- Mapping: `.migration/03_mapping_spec.{md,json}` v1.2 (APPROVED)
- Tolerances: `.migration/02_tolerances.{md,json}` v1.0 (APPROVED, STOP A)
- Canonicalization: `.migration/recon_canonicalization.json` v1.2
- Target db: `ow_tp_mongodb_032752`; every document carries `ns: "mongo_032752"`.
- Registered write targets: `ow.notifications` (sole owner) and the
  `dunning_attempts[]` array inside `ow.invoices` documents. The `ow.invoices`
  co-write is the coordinated U5→U6 sequential batch write pre-authorized by the wave
  plan and registered in `.migration/04_progress.md`; U6 adds the array and touches no
  other invoice field, root or embedded.

## Mapping rows

| Collection | Root table | Rows | `_id` (key strategy) | Fields |
|---|---|---:|---|---|
| `invoices.dunning_attempts[]` | `DUNNING_ATTEMPTS` | 1 | element key `attempt_no` (source `ATTEMPT_NO`), parent key `INVOICE_ID` | `id`, `tenant_id`, `scheduled_for`, `status_cd` |
| `notifications` | `NOTIFICATIONS` | 1 | source `ID` verbatim | `tenant_id`, `kind_cd`, `sent_at` |

Row counts are the NS=demo fixture counts and are checked by the loader and the
reconciliation harness. Oracle is read-only after fixture seeding. Attempts are embedded
under their parent invoice ordered by `attempt_no`; an invoice with no attempts carries
an explicit empty `dunning_attempts: []`. The contract expects zero orphan attempts
(every `INVOICE_ID` resolves to an `INVOICES` row) and zero duplicate
`(invoice_id, attempt_no)` pairs; either is an undeclared anomaly and halts the load.
`INVOICE_ID` is not stored on the element — it is the parent document key.

## Type contract applied to this unit

| Oracle | Columns here | BSON | Canonicalization |
|---|---|---|---|
| VARCHAR2 | attempts `id`, `tenant_id`; `tenant_id` | string | `empty_string_is_null` |
| DATE | attempts `scheduled_for` | date | UTC, truncate to milliseconds |
| TIMESTAMP(6) | `sent_at` | date | UTC, truncate to milliseconds |
| NUMBER(4,0) | attempts `attempt_no`, `status_cd`, `kind_cd` | int | — |

Source NULL becomes an explicit BSON null; NULL is not missing.

## Index plan

- `notifications`: unique `(tenant_id, kind_cd, sent_at)` — the verbatim source unique
  constraint, and the structure that carries the `sp_suspend_overdue` dedup contract
  (the source's conditional `NOT EXISTS` insert becomes a filtered upsert whose
  uniqueness the index enforces).
- `invoices`: no new index. The source unique `(invoice_id, attempt_no)` is preserved
  structurally by the `attempt_no` element key inside the single invoice document; the
  loader asserts it and the scheduling write is guarded on it.

No other collection or database is written by the U6 load.

## Stored-procedure replacement (`PKG_DUNNING`)

| Source object | Replacement |
|---|---|
| `fn_overdue_accounts` | `DunningService.overdue_accounts` |
| `sp_schedule_dunning` | `DunningService.schedule_dunning` |
| `sp_suspend_overdue` | `DunningService.suspend_overdue` |
| `JOB_NIGHTLY_DUNNING` (DBMS_SCHEDULER, `enabled => FALSE`) | `scripts/tp_mongo/job_nightly_dunning.py` |

The application port preserves: the overdue scan over `status_cd = 40` invoices with
Oracle's date-only comparison (`TO_CHAR(...,'YYYYMMDD')` strictly less than the as-of
day) and `TRUNC(as_of) - TRUNC(issued_at)` day counting; the outer join to `tenants`
with `DECODE(status_cd, 10 'active', 20 'suspended', 'UNKNOWN')` so a missing tenant
reports `UNKNOWN`; the `issued_at, id` ordering; per-invoice next attempt
`NVL(MAX(attempt_no), 0) + 1`; the weekend shift of the scheduled date (Saturday +2,
Sunday +1, otherwise the as-of day); deterministic attempt id
`md5_uuid(invoice_id || attempt_no)`; new attempts written with `status_cd = 10`; the
source's swallow-on-insert-error behaviour (`WHEN OTHERS THEN NULL`), reproduced as a
guarded write on the `attempt_no` element key so a duplicate is a silent no-op rather
than a second element; the package state `g_last_run_dt` / `g_scheduled_cnt` exposed as
the service's run metadata; the 14-day suspension threshold on the same date-only
comparison; suspension applying only to tenants currently in status `10`, moving the
tenant and its `status_cd = 10` subscriptions to `20` with `suspended_on = TRUNC(as_of)`;
and the conditional suspension notification (`kind_cd = 3`, `sent_at = TRUNC(as_of)`,
id `md5_uuid(tenant_id || 'suspension' || YYYY-MM-DD(as_of))`) whose `NOT EXISTS` guard
becomes an insert-if-absent upsert on `(tenant_id, kind_cd, sent_at)` backed by the
unique index — so a second run of the same day inserts nothing.

`sp_suspend_overdue` is a single Oracle transaction; the port runs the whole call in one
MongoDB session transaction, preserving that boundary. `sp_schedule_dunning` is
deliberately NOT transactional: its per-insert exception swallow means an individual
failed attempt must not roll back the ones already scheduled. Distinct suspension
candidates are iterated in `tenant_id` order (the source `SELECT DISTINCT` has no
`ORDER BY`; per-tenant work is independent, so the order is a determinism choice only).

Suspension writes to `ow.tenants` (U0) and `ow.subscriptions` (U3) are the migrated
runtime behaviour of the source procedure, not U6 load targets: they are exercised only
by transcript replay, and the replay restores the baseline by re-running the owning
units' idempotent loaders before every scenario.

The Oracle audit-log write is suppressed: U7 owns `billing_audit_log`. The service
retains the audit sink seam with the source message strings.

## Scheduler replacement

`JOB_NIGHTLY_DUNNING` is defined in `schema/04_jobs.sql` with `enabled => FALSE` — the
nightly dunning run is dormant in the source estate. The migration preserves that state:
`scripts/tp_mongo/job_nightly_dunning.py` is a documented, manually runnable entrypoint
that performs the job action verbatim — `schedule_dunning(as_of)` then
`suspend_overdue(as_of)`, defaulting to today (UTC) as `TRUNC(SYSDATE)` does. No cron,
systemd timer, Atlas trigger, or other schedule is created or activated by this unit.

Recon for this unit is a child self-check (`run_mode=fixture`): the harness runs against
the deterministic read-only `NS=demo` Oracle fixture. The CLI exposes that as
`--mode live` (its modes are `live`, `snapshot`, `continuous`), as the prior unit
wrappers do. The parent owns the independent live gate. Stored-procedure parity is
evidenced by replaying the recorded Oracle transcripts in
`procs/oracle/transcripts/dunning/*.json` against the migrated service.
