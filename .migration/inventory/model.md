## Access patterns (from app code) and what they decide

| Path | Oracle today | Mongo read | Decides |
|---|---|---|---|
| GET /billing/customer | `customer_master WHERE tenant_id ORDER BY cust_seq_no FETCH FIRST 1` + EAV `WHERE entity_id ORDER BY eav_id` | one `customers` find, sort `cust_seq_no` | EAV embedded (always read with the customer, max 5/customer); index `{tenant_id, cust_seq_no}` |
| GET /billing/invoices, /invoices/:id/lines | PKG_INVOICING over INVOICES/INVOICE_LINES `ORDER BY line_no` | `billing_invoices` by tenant; lines from the doc | lines embedded; index `{tenant_id, issued_at}` |
| admin month-end / reconciliation | INVOICE_HEADER x INVOICE_LINE x CODES by `batch_no`; CUSTOMER_MASTER sums by batch | aggregations on `invoices` (+`$unwind lines`) and `customers` | lines embedded (read with header, max 23); indexes `{batch_no, status_cd}`, `{conversion_batch_no}` |
| plans, me, entitlement, plan-change, usage, dunning | PKG_PLANS/RATING/INVOICING/DUNNING | per-collection reads/writes | small tables stay separate collections: each is written on its own path (plan-change, rating upsert, dunning), shared by several readers |

## Type and value decisions

- NUMBER(p,s>0) -> Decimal128; NUMBER(p<=9,0) -> int; NUMBER(p>9,0) -> long. DATE/TIMESTAMP -> date
  (0 sub-millisecond values: `ts_submillisecond` all 0, so ms truncation is lossless).
- VARCHAR2/CHAR stored verbatim (CHAR right-trimmed; all CHAR columns are CHAR(1)). Text dates
  (`*_DT` VARCHAR2), Y/N flags and CSV lists are **not re-typed**: SIGNUP_DT has 50 values that no
  date format parses and RELATED_ACCT_IDS has 26 malformed lists, and the Account page shows these
  columns as stored. Typed copies can be added later without a migration.
- NULL and '' are omitted from documents (tolerances v1). The Mongo backend fills every mapped
  column back as `null`, so the Account page still lists all 155 legacy fields.
- Embedded line keys: LINE_ID (unique; 19,512 duplicate `(invoice_id, line_no)` groups make line_no
  unusable). Order `line_no, line_id`; attributes order `eav_id`.
- INVOICE_LINE's INVOICE_ID/INVOICE_NO/CUST_ID/TENANT_ID are dropped from embedded lines: 0
  mismatches against the header over 149,963 rows (`line_vs_header_denorm`). Quarantined lines keep
  every column.
- Duplicate attributes stay separate elements (187 name groups, 379 rows).
  Recon compares them by element key EAV_ID.
- Codes stay numeric; `codes` resolves labels (reports use INV_STATUS).
- Unsharded: ~205k documents, largest document < 40 KB.

| Unit | Sources | Write targets (ow_tp_mmp_live) |
|---|---|---|
| U1-customers | CUSTOMER_MASTER, ENTITY_ATTR_VALUE | customers |

| U4-app-backend | (code) legacy-billing `BILLING_BACKEND=mongo`, pinned pymongo, Mongo fixture container in Compose + CI, contract/parity tests | none live; fixture container only |

One wave, 4 batches, disjoint write targets, `auto_merge: false`. Recommended execution: single
session at width 1 (~205k rows total), then `!mongo_reconciliation` per unit in one fresh session.
Each data unit develops against the local fixture (`fixtures/oracle-mmpfix.manifest.json`) and reads
the EC2 once. Load: bulk ReplaceOne(upsert) by `_id`, then delete docs not in the loaded key set
(idempotent reload, readWrite only).
