# Pipeline 2, wave 2 close — PASS: `p2-custbill-parse` on Lakeflow, official live recon green

Landed: 1 of 1 batch, 1 of 1 unit (`p2-custbill-parse`). Failed: none. Blocked: none. Circuit breaker: 0 of 3.

What the unit replaces: `etl/legacy-extra/jobs/parse_custbill_fixedwidth.sh`. `ow_tp.silver.custbill` now parses the fixed-width record from bronze raw bytes and reproduces the legacy `.psv` line byte for byte, including every defect the contract pins: trailing spaces stripped from `cust_id`, `cust_name` and `currency` only; the amount read as a `strtod`-style numeric prefix (`12AB` → `0.12`) and divided by 100, sign and all; the date string-sliced with no validity check (`20259999` → `2025-99-99`); missing values as empty strings, never NULL; and a `|` byte inside a name left shifting every later field, because repairing it would change the finance total. Silver stores the rendered `psv_line` next to the sliced columns so gold can aggregate a re-split of that line (C-5.1, P2-D03).

Quarantine is additive and cannot gate output. All ten expectations are `expect_all` (warn), a failing row is **copied** to `ow_tp.bronze.custbill_quarantine` with its raw bytes and the names of the checks it failed, and the same row stays in silver and flows to gold. Evidence, not assertion: 116 silver rows, 14 quarantined, 0 quarantined rows missing from silver (contract C-6.3, P2-D02).

Recon: official harness verdict **PASS**, `merge_eligible=true`, live, depth full, mapping `map-p2-v1`, tolerances `v1` — tier 3 keyed diff over all 116 records with zero findings. The source side is the legacy parser's own captured `.psv` output, loaded independently into `ow_tp.bronze.custbill_legacy_baseline_psv` and keyed by the physical record number of the `.dat` line it came from; the target side recomputes from the raw `.dat` bytes and never reads that table. The compared column is the whole `psv_line`, which is stricter than a field-by-field compare and the only sound one — the legacy's positional `|` split and the target's byte slices disagree by design on the collision record, so a field diff there would measure the comparison rather than the parse. Report: `.migration/recon/p2-custbill-parse/p2-custbill-parse.recon.json`.

Idempotency was proven by rerunning the pipeline, not inferred: silver, quarantine and the trailer audit are byte-identical across updates — silver 116 rows md5 `115f7e40240d7529b6bc48ec0a922ccd`, quarantine 14 rows md5 `158d9647f29bfa8713db13190b1deef3`, audit 6 rows md5 `c286f2cd16e1168b779e31521c768835` (`idempotency.before.json`, `idempotency.after.json`).

**Behaviour changes:** none new in this wave. **P2-D01 still stands**, named here rather than only in a recon JSON: the legacy chain can parse a half-written `.dat` (1-second double-stat, parse five minutes later) and the target cannot, because landing is atomic and parse is a dependency edge.
