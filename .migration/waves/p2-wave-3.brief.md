# Pipeline 2, wave 3 close — PASS: `p2-finance-close` on Lakeflow, official live recon green

Landed: 1 of 1 batch, 1 of 1 unit (`p2-finance-close`). Failed: none. Blocked: none. Circuit breaker: 0 of 3.

What the unit replaces: `etl/legacy-extra/jobs/finance_excel_report.pl`. `ow_tp.gold.custbill_finance_close` is the finance close as a governed table — totals and counts by currency and record type — and the job task `ow_tp_p2_custbill_finance_close_export` writes the same report as a file to `/Volumes/ow_tp/gold/exports/custbill/finance_billing_<stamp>.csv` plus the `.xls` twin, which is a byte copy of the CSV and not a spreadsheet. The sendmail pipe is gone; the job's own failure notification replaces it in wave 4 (D-007 / D4-01, confirmed by the user at STOP E).

The aggregation reproduces the Perl, defects included. It re-splits the rendered `psv_line` positionally on `|` instead of reading silver's clean columns, so the delimiter-collision record still lands in the nonsense group `0US|D0` — grouping the clean columns would repair the defect and change the totals. Amounts are coerced the way the Perl coerced them (leading numeric prefix, junk contributes zero but still counts a row); `usd` and `USD` stay separate groups; unknown record types keep their raw bytes in `UNKNOWN(<raw>)`; and rows whose first positional field is empty are skipped, which is the only row the legacy skips. `row_order` and `sort_key` materialize the report's `sort keys %tot` ASCII ordering, so an ordering regression fails the gate instead of passing as a set match.

Nothing is filtered on the way to gold. Every silver row reaches the aggregation, quarantined or not: 116 silver rows in, 114 records counted in gold, and the 2-row gap is exactly the empty-customer rows the Perl also skips — the same 114 the captured legacy report counted. No expectation dropped a record (STOP C condition, contract C-6.3).
