Skill feedback to fold in:
- Fixture-first plus a shared target is a trap for the idempotency rerun: the fixture is a subset of the same keys and the loader deletes source-dropped keys, so replaying the fixture load after the live load would have deleted 804 live rows. Prove idempotency with a second live load and record the deviation.
- Oracle reserved words bite in op SQL: `prior`, `level` and `size` as column aliases fail with ORA-00923, which reads like a syntax error rather than a naming one.
- Oracle LEAST/GREATEST return NULL if any argument is NULL; Postgres ignores NULLs. Write the Oracle behaviour explicitly where a NULL path depends on it.
- Oracle ADD_MONTHS is month-end aware; `- interval '3 months'` is not an equivalent.
- Oracle's unformatted TO_CHAR(number) drops a trailing .00 and the leading zero; numeric::text does not, so any log or audit message carrying a number diverges unless it is normalised.
- DUP_VAL_ON_INDEX is not always ON CONFLICT: when the source's UPDATE branch touches fewer columns than the INSERT, ON CONFLICT DO UPDATE silently resets the rest. Insert-then-catch unique_violation is the faithful form.
- An idempotency digest over a target with a sequence PK or a localtimestamp default never matches; exclude those columns by name and record the exclusion instead of reading it as a parity failure.
- The read-only Oracle user has no EXECUTE, so a live package call has to be inlined and package-call equality stays fixture-only.
- The degraded recon driver needs PYTHONPATH pointed at the plugin harness; it is not importable from the snapshot's python3, and psycopg/oracledb are missing from the session python3.
